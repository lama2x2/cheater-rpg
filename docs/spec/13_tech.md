# 13. Техническая спецификация

Статус: **предложение**. Пункты с меткой D-xx ждут решения в `docs/decisions.md`.

## 13.1 Движок и язык
- **Godot 4** (последняя стабильная 4.x на момент установки; версию фиксируем в
  `project.godot` и README и не меняем без причины).
  - Почему: нативно на macOS (Apple Silicon), бесплатный, без роялти, лёгкий (~100 МБ), экспорт в
    `.app`/Windows/Linux из одного проекта, текстовые форматы сцен (удобно для git и для ИИ).
  - Почему не браузер: ограничения по памяти/потокам/файлам, слабее производительность на толпах
    тварей, неудобные сохранения. Почему не Unreal: тяжёлый, C++/Blueprints хуже для работы с ИИ
    и одного разработчика. Почему не Unity: лицензионные риски, тяжелее для маленькой команды.
- **GDScript со строгой типизацией** (D-27; альтернатива — C#). Для горячих мест (симуляция толп)
  — возможен GDExtension на C++/Rust позже, только по замерам.

## 13.2 Вид и графика (D-04)
Рекомендация: **3D low-poly с ортографической изометрической камерой**.
- Плюсы: дешёвые/бесплатные ассеты (Kenney, Quaternius, позже платные паки), свет и ночь «из
  коробки», поворот камеры, высота (крыши, обрывы, Ступень), не нужно рисовать спрайты в 8 направлениях.
- Минусы: моделирование своего контента сложнее, чем пиксель-арт.
- Альтернатива: 2D изометрия (TileMap) — дешевле по коду, дороже по арту.

## 13.3 Архитектура
Ключевой принцип: **симуляция отдельно от отображения**. Правила игры (характеристики, трофеи,
таймеры, популяции) — чистый код без сцен, тестируемый в headless-режиме. Сцены только показывают
состояние и передают ввод.

```
┌─────────────────────────── Presentation (сцены) ───────────────────────────┐
│ Player, Enemy, ClusterScene, HUD, Inventory UI, Map UI, Dialog UI          │
└──────────────▲───────────────────────────────▲──────────────────────────────┘
               │ сигналы EventBus               │ команды
┌──────────────┴───────────── Game Services (autoload) ───────────────────────┐
│ GameClock   — мировое время, сутки, ускорение сна                           │
│ WorldSim    — регионы, кластеры, таймеры перезагрузки, популяции, миграции  │
│ PlayerState — характеристики, шкалы, жизни, инвентарь, умения               │
│ PartyState  — спутники, доверие, жизни спутников                            │
│ SystemLog   — генерация и хранение сообщений Системы                        │
│ Content     — загрузка и валидация данных из data/                          │
│ SaveService — сохранение/загрузка, версии и миграции                        │
│ Rng         — сидируемые генераторы (мир, лут, бой) для воспроизводимости   │
│ EventBus    — глобальные сигналы                                            │
└──────────────▲──────────────────────────────────────────────────────────────┘
               │ использует
┌──────────────┴───────────────── Core (чистые классы, RefCounted) ───────────┐
│ StatBlock, ProgressRules, DeathRules, TrophyRules, LootTable, SkillRules,   │
│ ClusterLifecycle, PopulationModel, NoiseModel, DamageModel, TrustModel      │
└─────────────────────────────────────────────────────────────────────────────┘
```

### Симуляция мира по уровням детализации
| Уровень | Где | Как |
|---|---|---|
| **Полный** | кластер с игроком (+соседи у границы) | реальные агенты, навигация, физика |
| **Средний** | соседние кластеры | агенты без анимации, упрощённое движение (для миграций и шума) |
| **Абстрактный** | все остальные | числа: популяция по стадиям, «съедено», лут-индекс, тик раз в игровой час |
- При входе игрока кластер «материализуется» из абстрактного состояния (детерминированно по сиду).
- Орды: агенты в ядре — MultiMesh + flow field, отдельные твари выделяются только вблизи.

### Сцены кластеров
- Шаблон кластера = вручную собранная сцена (рельеф, здания, точки спавна, точки лута, респы).
- При загрузке: шаблон + сид перезагрузки → лут и популяция.
- Переход между кластерами: подгрузка соседнего в фоне (`ResourceLoader.load_threaded_request`),
  граница как триггер (D-07: бесшовно или с короткой загрузкой).

## 13.4 Данные и контент
- Весь баланс — в `data/` текстом (**JSON**, D-29; альтернатива — Godot `.tres`): характеристики,
  твари, таблицы лута, трофеи, умения, шаблоны кластеров, регионы, диалоги, тексты лога.
- Схемы — 14_content_data.md. При старте `Content` валидирует данные; ошибка → понятное сообщение.
- Тексты — через `tr()` и CSV/PO локализации с первого дня.

## 13.5 Сохранения
- Формат JSON в `user://saves/` (на Mac: `~/Library/Application Support/Godot/app_userdata/<Проект>/`).
- Поле `save_version` и цепочка миграций.
- Автосохранение: при входе в стаб, при смерти (после штрафов — чтобы не было сейвскама), раз в
  N минут. Ручное — только в стабе (D-30, влияет на хардкорность).
- Сохраняем: мировое время, абстрактное состояние всех кластеров, состояние текущего кластера
  (агенты, лут, тела), игрока, отряд, задания, лог, сиды.

### Как устроено (M1, задача 1)
- `src/core/save_format.gd` (`SaveFormat`) — чистые правила: конверт
  `{"save_version", "saved_at", "sections": {...}}`, цепочка миграций `MIGRATIONS = {K: Callable}`
  (каждая переводит версию K в K+1), атомарная запись (`*.tmp` → переименование), чтение с
  миграцией. Сохранение из более новой версии или с дырой в цепочке не грузится (лог Системы).
- `SaveService` (autoload) собирает секции: объект с `to_dict()` / `load_dict(data)`.
  Сервисы подключены сразу (`clock`, `player`, `log`), объекты сцены регистрируются сами
  (`hero` — позиция и поворот героя) через `SaveService.register()` / `unregister()`.
  Новая система с состоянием = новая секция; поменялся формат секции = `VERSION + 1` и миграция.
- Слоты: `user://saves/<слот>.json`. `auto` — автосейв при смерти (после штрафов), `debug` — F5/F9.
- Лог Системы в сохранении — последние 200 сообщений.
- Пока не сделано: автосейв при входе в стаб и по таймеру (задачи 11–12), ручное сохранение в
  баре стаба (задача 12), меню выбора слота.

## 13.6 Структура репозитория (план)
```
cheater-rpg/
  project.godot
  addons/            # сторонние плагины (тест-фреймворк и т.п.)
  assets/            # модели, текстуры, звук (D-28: Git LFS?)
  data/              # JSON-контент
  src/
    core/            # чистые правила (без Node)
    services/        # autoload-сервисы
    world/           # кластеры, спавн, ИИ
    actors/          # игрок, твари, люди
    ui/              # HUD, меню, экраны
  scenes/            # .tscn
  tests/             # юнит-тесты core и data
  docs/
  scripts/           # run.sh, build_mac.sh, test.sh
```

## 13.7 Тесты
- Свой мини-раннер `tests/run_tests.gd` (D-31): файлы `tests/test_*.gd` наследуют
  `tests/test_case.gd`, методы `test_*` запускаются по очереди. Запуск — `scripts/test.sh`
  (плюс дымовой прогон главной сцены без окна, падает на любой `SCRIPT ERROR`).
- Раннер стартует в `_initialize()`: autoload-сервисы уже есть, поэтому тесты могут грузить
  скрипты, которые на них ссылаются (`player_state.gd`, `game_clock.gd`). `SCRIPT ERROR` внутри
  теста обрывает метод незаметно для раннера — его ловит `scripts/test.sh` и валит прогон.
- Юнит-тесты на всё в `src/core/` (формулы, штрафы смерти, лут-таблицы, таймеры).
- Тест валидности всех файлов `data/`.
- Headless-запуск из терминала (`godot --headless ...`) — для ИИ-ассистента и будущего CI.

## 13.8 Запуск и сборка на macOS
### Установка Godot (делает пользователь)
Вариант 1 — Homebrew:
```bash
brew install --cask godot
```
Вариант 2 — скачать с godotengine.org, положить в `/Applications`.
CLI: `godot` в PATH (brew делает сам) или `/Applications/Godot.app/Contents/MacOS/Godot`.

### Запуск из исходников
```bash
godot --path /Users/lama4/Documents/читер/cheater-rpg
```
Редактор: `godot -e --path …`.

### Сборка `.app`
1. Установить export templates (Editor → Manage Export Templates; ~1 ГБ).
2. Пресет «macOS» в `export_presets.cfg` (в git, без секретов).
3. `godot --headless --export-release "macOS" build/CheaterRPG.app`
- Подпись: ad-hoc (по умолчанию) — запускается на своём Маке. Если macOS блокирует —
  правый клик → «Открыть» или снять карантин `xattr -dr com.apple.quarantine build/CheaterRPG.app`.
- Нотаризация (для раздачи другим) требует Apple Developer ($99/год) — не сейчас.
- Windows `.exe` и Linux собираются с того же Мака (шаблоны есть), но тестировать надо на них.

## 13.9 Производительность (ориентиры)
- Цель: 60 FPS на Apple Silicon M1 при 200 активных тварях в кадре; 2000+ в орде через MultiMesh.
- Бюджет тика абстрактной симуляции: < 2 мс на игровой час для 40 кластеров.
- Профилирование встроенным профайлером Godot перед каждым этапом.
