# Стек

Итог: **Python 3.12 + aiogram 3 + сюжет в YAML + SQLite**. Ink не берём: выигрыш небольшой, а
в Python у него нет официального рантайма. LLM в первой версии нет.

## 1. Ink или свой формат — честное сравнение

Что даёт Ink:
- **Inky** — редактор с живым превью: пишешь и сразу играешь ветку.
- Синтаксис «плетения» (weave) для прозы с частыми мелкими развилками и сборками; переменные,
  условия, счётчики посещений — из коробки.
- Проверенный язык (на нём сделаны 80 Days, Sorcery!, Heaven's Vault).

Чего Ink не даёт нам:
- **Наша структура — сторилеты**: колоды сцен по кластерам, выпадающие по условиям, плюс
  ресурсы и проверки. В Ink этого нет; выбор сцены, броски, шкалы и таймер всё равно пишутся в
  движке, а Ink остаётся «текстом внутри сцены».
- **Python-рантаймы — сторонние и маленькие** (проверено 2026-10-20):
  - `bink` — Python-обёртка над Rust-портом `bladeink` (сам порт живой: 2.1.0 от 2026-10-17,
    внешние функции, наблюдатели переменных, сохранение состояния). Обёртка — 9 звёзд, без
    релизов на GitHub, бинарные колёса под платформы. Работать, вероятно, будет, но мы будем
    зависеть от одного человека.
  - `inkpython` — чистый Python, порт inkjs, 5 коммитов, 0 звёзд. Для игры — рискованно.
  - Официальные рантаймы — только C# и JS (inkjs). Взять Ink «по-честному» = **TypeScript +
    inkjs**; тогда и бот на TS (grammY).
- Сцены у нас короткие (до ~700 знаков, 2–4 выбора), развилок внутри сцены мало — сила weave
  почти не нужна.

Что даёт свой YAML:
- Сцена = одна запись: текст, условия, варианты, проверка, последствия. Читается и правится
  без нового языка; Claude пишет черновики прямо в этом формате.
- **Проверка веток** — свой скрипт `tools/lint_story.py` (это и есть замена Inky для нас):
  все `goto` ведут в существующие сцены; нет недостижимых сцен и тупиков без выхода; флаги и
  качества, которые читаются, где-то пишутся; длина текста ≤ лимита Telegram; у проверки есть
  обе ветки.
- **Автоигрок** `tools/autoplay.py`: тысячи случайных прохождений без Telegram — ищет
  зависания, недостижимые концовки, слишком лёгкие/тяжёлые дни, считает распределение концовок.
- **Превью** — `tools/play_cli.py`: та же игра в терминале, без бота.

| | Ink + TS (inkjs) | Ink + Python (bink) | **YAML + Python** |
|---|---|---|---|
| Писать прозу | лучше всех (Inky) | Inky | обычный редактор, превью — CLI |
| Сторилеты, ресурсы, проверки | в движке, Ink — текст | в движке | всё в одном формате |
| Проверка веток | Inky + свой код для сторилетов | то же | линтер + автоигрок |
| Риск зависимостей | низкий | **средний** (маленький проект) | нет |
| Сложность для пользователя | новый язык + TS | новый язык | YAML, близко к JSON в `data/` |

**Выбор: YAML + Python.** Вернуться к Ink, если текста станет больше ~50 тыс. слов или
появится отдельный автор, которому нужен Inky; тогда честнее TS + inkjs, чем Python + bink.

## 2. Формат сюжета (черновик)

```yaml
# content/clusters/village.yaml
- id: village.well
  deck: c_village            # колода кластера
  weight: 3
  when: { noise: "<4", not_flag: well_seen }
  text: |
    Колодец у сельсовета. Цепь уходит вниз и натянута, будто
    на ней что-то висит. Тяжёлое.
  choices:
    - label: Вытянуть цепь
      check: { stat: strength, dc: 9, kind: white }
      success: { set: [well_seen], gain: { sporans: 4 }, goto: village.well_bag }
      fail:    { noise: +1, wound: 1, text: Цепь срывается и грохочет вниз. }
    - label: Посветить и присмотреться
      check: { stat: insight, dc: 7 }
      success: { set: [well_seen, cult_sign], text: На камне — выжженный знак Пепельных. }
      fail:    { text: Темно. Пахнет кислым. }
    - label: Не трогать
      goto: end
```
- Сюжетные сцены — `content/story/day1.yaml` и т. п., те же поля плюс `day`, `faction`.
- Тексты Системы — `content/system.yaml`: ключ → несколько вариантов (как `ru.json` в Godot).
- Схема проверяется pydantic при загрузке; линтер — в CI.

## 3. Бот
- **aiogram 3**: роутеры, фабрика `CallbackData` (≤ 64 байт: `c:<сцена>:<выбор>:<nonce>`),
  middleware для белого списка и очереди на пользователя (`asyncio.Lock`).
- Движок — чистые функции без aiogram: `apply(state, choice, rng) -> (state, events)`. Бот только
  рисует экраны. Так работают CLI, автоигрок и тесты (pytest).
- Случайность — `random.Random(seed)` в состоянии игрока: повторяемо для отладки.
- Экран редактируется на месте (`edit_message_text`), Система — отдельными сообщениями; HTML
  (`<b>`, `<i>`, `<blockquote>`). Всегда `answer()` на нажатие; ~1 сообщение в секунду на чат.

## 4. Хранение
**SQLite** (WAL, `aiosqlite`) — одного файла хватит с запасом.

| Таблица | Что |
|---|---|
| `players` | `tg_id`, имя, допуск (белый список), создан |
| `runs` | текущее прохождение: `state` (JSON — шкалы, статы, флаги, фракции, колоды, таймеры), `version` для защиты от двойных нажатий, `content_version` |
| `meta` | между прохождениями: концовки, «Мементо», скрытые характеристики, известные таймеры |
| `log` | строки Системы (последние 200) |

- Сохранение после каждого выбора в одной транзакции. Устаревшая кнопка (не тот `nonce`) —
  «Это меню устарело».
- Обновили текст — `content_version` растёт; если сцена игрока пропала, движок возвращает его в
  хаб с извинением Системы.
- Бэкап — раз в сутки копия файла за пределы сервера. Postgres — только для публичного бота с
  тысячами игроков.

## 5. Развёртывание
- Long polling, один процесс, VPS 1 vCPU / 1 ГБ (или домашний Mac на время теста); `systemd`
  или Docker. Токен — в `.env`.
- Код бота — папка `textgame/` в этом репо с файлом `.gdignore` (чтобы Godot её не сканировал) или
  отдельный репозиторий. Общего кода с Godot нет, так что отдельный репо чище — решим при старте.

## 6. LLM — не в первой версии
Сюжет авторский, текста немного — шаблонов достаточно. Если позже захочется живых реплик (слухи,
торг), принцип как в D-78: исходы решает движок, модель пишет только «обёртку» с фолбэком на
текст из YAML, голос Системы — всегда руками. Порядок цены облачной маленькой модели (Claude
Haiku 5.5, цены 2026-10): ~$0,0002 за реплику.
