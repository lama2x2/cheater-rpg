# Стек и устройство движка

**Python 3.12 + aiogram 3 + pydantic + PyYAML + SQLite (stdlib `sqlite3`) + Docker.** Код —
`textbot/`. Ink не берём: история — короткие сцены с условиями и эффектами, это ложится в YAML,
а Python-рантаймы Ink сторонние и маленькие (`bink` — обёртка над Rust-портом `bladeink`,
`inkpython` — 0 звёзд; проверено 2026-10-20). Если когда-нибудь понадобится Inky для большого
текста — честнее TypeScript + inkjs.

## Модули
| Модуль | Что |
|---|---|
| `expr.py` | безопасный язык условий и эффектов: свой токенизатор и парсер, без `eval`; только имена `flag/var/item/time/steps/lives/deaths/mode/meta` |
| `model.py` | схема кампании (pydantic, лишние ключи — ошибка), загрузка YAML, проверка синтаксиса всех выражений при загрузке |
| `engine.py` | чистые функции: `new_run`, `set_name`, `view`, `choose`, `record`; броски с сидом (`seed:run:steps`), отложенные эффекты, лимит времени, смерть по режиму, контрольные точки |
| `render.py` | экран → HTML для Telegram / текст для терминала; `/status`, «Мементо» |
| `storage.py` | SQLite: `users` (заявки: pending / approved / denied / blocked, кто и когда решил), `players`, `slots` (3 на игрока), `meta`; сохранение одной транзакцией; бэкап через SQLite backup API |
| `service.py` | логика бота без Telegram: команды и кнопки → экраны (её гоняют тесты) |
| `bot.py` | aiogram: доступ по заявкам (админ пускает кнопкой), очередь на игрока, правка старого сообщения, heartbeat, ежедневный бэкап |
| `lint.py`, `play.py`, `autoplay.py` | линтер, игра в терминале, случайные прохождения |

## Надёжность сохранений
- Состояние прохождения — один JSON в `slots.state`; после **каждого** выбора: загрузить →
  применить → записать в транзакции (`BEGIN IMMEDIATE` … `COMMIT`), WAL, `synchronous=FULL`.
  Сначала запись, потом ответ в Telegram.
- Кнопка несёт `c:<слот>:<номер шага>:<выбор>`. Номер шага не совпал (старая кнопка, двойное
  нажатие) — «Экран обновлён» и текущий экран. Рестарт бота ничего не теряет: `/start`, любая
  кнопка или любое сообщение перерисовывают текущий экран из базы.
- Мета (концовки, «Мементо», число прохождений) — отдельная таблица на игрока и кампанию; «начать
  заново» её не трогает.
- Кампания поменялась и сцены игрока больше нет — бот предлагает меню вместо падения.

## Docker
`Dockerfile` (python:3.12-slim) + `docker-compose.yml`: `restart: unless-stopped`, `./data:/data`
(база, бэкапы, логи), `./campaigns` только для чтения, токен и id админов — из `.env`
(`.env.example` рядом). Healthcheck — свежесть файла `/data/heartbeat` (бот обновляет его раз в
30 с). Неверный токен — понятная строка в логе и пауза 60 с перед перезапуском.

## LLM
Не нужен на старте. Если понадобится — как в D-78: исходы решает движок, модель пишет только
текст поверх, с фолбэком на YAML; голос Системы — руками.
