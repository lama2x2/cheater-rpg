# Стек текстовой версии

Итог сверху: **TypeScript + grammY + inkjs + SQLite**, бот в папке `bot/` этого же репозитория,
читает `data/` напрямую. LLM-рассказчик — не в MVP; потом, если захочется, — облачная маленькая
модель поверх детерминированных правил с фолбэком на шаблоны. Python + aiogram — равноценная
замена, если удобнее Python (разница — в Ink, см. ниже).

## 1. Язык и библиотека бота

| | **TypeScript + grammY** | **Python + aiogram 3** |
|---|---|---|
| Порт правил из GDScript | классы и строгие типы ложатся 1:1 (`class`, `enum`, типизированные поля) | синтаксис ближе к GDScript (отступы, `func` → `def`), типы — подсказки, не проверка |
| JSON из `data/` | родной формат; схемы и проверка — zod | `json` из коробки; схемы — pydantic |
| Сцены на Ink | **inkjs — официальный рантайм Ink**, есть и компилятор (`inkjs/full`) | официального рантайма нет; неофициальные порты — проверять качество и поддержку, или свои JSON-сцены |
| Кнопки и диалоги | плагины меню и «разговоров» (conversations), сессии с хранилищем | FSM, роутеры, фабрики callback-данных, middleware |
| Асинхронность | event loop Node, очередь на пользователя — промис-цепочка | asyncio, `asyncio.Lock` на пользователя |
| SQLite | `better-sqlite3` (синхронный, быстрый) или встроенный `node:sqlite` | `sqlite3` из стандартной библиотеки, `aiosqlite` |
| Картинка карты (позже) | SVG → PNG (`@resvg/resvg-js`) | Pillow |
| Тесты | vitest | pytest |
| Сообщество | grammY хорошо документирован, в т.ч. по-русски | aiogram — очень большое русскоязычное сообщество |

**Рекомендация — TypeScript + grammY.** Решают три вещи: Ink работает в JS официально (сцены
пролога, крестин и неписей пишутся в Inky и проверяются там же); JSON и zod-схемы дают проверку
данных Godot-версии на старте бота; строгие типы ловят ошибки порта правил. Если пользователю
важнее читать код бота самому и Python ближе — aiogram, а сцены — своим JSON (как реплики `npc` в
`ru.json`, D-23), без Ink.

## 2. Хранение

**SQLite в режиме WAL** — одного файла хватит на сотни игроков: мир у каждого свой и маленький
(6 кластеров, популяции, трупы, инвентарь — десятки КБ JSON).

| Таблица | Что | Зачем |
|---|---|---|
| `players` | `tg_id`, имя, создан, `allowed` (белый список), настройки | доступ, `/about` |
| `saves` | `tg_id`, `version` (число для оптимистичной блокировки), `format` (версия формата), `state` (JSON) | весь мир игрока одним документом |
| `system_log` | `tg_id`, игровое время, ключ, параметры, «лучшее» | лог Системы и «лучшие моменты» (D-37: последние 200 + лучшие без лимита) |
| `screens` | `tg_id`, `message_id` экрана, `nonce` | редактировать одно сообщение; отбрасывать нажатия старых кнопок |

- Состояние — один JSON по образцу секций сейва Godot (`player`, `world`, `stab`, `corpses`), но
  **свой формат** со своей версией и миграциями: совместимость с сейвами Godot не цель.
- Каждое действие: загрузить → применить правила → сохранить с `version + 1` в одной транзакции.
  Двойное нажатие: на пользователя — очередь, у кнопки — `nonce` экрана; устаревшая кнопка
  отвечает «Это меню устарело».
- Бэкап — `sqlite3 .backup` раз в сутки, копия за пределы сервера.
- **Postgres** — только если бот станет публичным с тысячами игроков или нескольких процессов
  (вебхуки за балансировщиком). Схема та же, `state` → `jsonb`. Для MVP — лишнее.

## 3. Где живёт бот и как читает `data/` без изменений

- Папка **`bot/`** в этом репозитории. В ней — файл **`.gdignore`**, чтобы Godot не сканировал
  `node_modules` и исходники бота. `node_modules`, база и `.env` — в `.gitignore`.
- Бот читает `../data/**/*.json` при старте. Правило: **`data/` — общая правда, бот её не
  правит**. Ключи `_doc` пропускаются. Поля, которые нужны только сцене (`body`, `color`,
  `ground_color`, размеры в метрах), бот игнорирует.
- Тексты: как в Godot, `data/text/ru.json` сливается с `ru_*.json` (имена предметов, тварей,
  лог, причины смерти, советы, эпитафии, происхождения, умения) — это готовые шаблоны для
  фолбэка рассказчика.
- Свои числа и тексты бота — отдельно: `bot/data/text_rules.json` (стоимость действий в минутах,
  раунд боя, шанс попадания тварей, шкала тревоги) и `bot/data/text/ru_bot.json` (экраны, кнопки).
- **Контрактный тест**: CI бота грузит все `data/*.json` через zod-схемы (только поля, которые бот
  читает, с `.passthrough()`) и падает, если Godot-сторона переименовала или убрала нужное поле.
  Так изменения основной игры не ломают бота молча.
- **Порт правил**, а не запуск GDScript: из 37 файлов `src/core/` (~4 300 строк) переносим ~30,
  без `key_bindings`, `settings_model`, `cluster_layout`, `vision_rules` (конус) и
  `infected_brain` (реалтайм). Юнит-тесты `tests/test_*.gd` переносим вместе с правилами — это
  проверка порта.
- **Случайность**: свой генератор с сидом (например, PCG32 или mulberry32) — мир игрока
  детерминирован по сиду и номеру действия, но **не совпадает** с миром Godot при том же сиде.
  Это нормально; для формул без случайности позже можно сделать «золотые» тесты (скрипт Godot
  выгружает результаты функций в JSON, бот сверяет) — это правка Godot-репо, отдельная задача.
- Запускать Godot headless как сервер правил — не стоит: тяжело (сотни МБ на процесс), медленный
  старт, неудобно делить на пользователей.

## 4. Сцены: Ink

- **Для чего**: пролог происхождения (13 вариантов + «Случайно»), крестины, первая смерть-обучение,
  разговоры с неписями стаба, события долгов (16.3). Не для боя и не для правил.
- **Как стыкуется**: выбор Ink → inline-кнопка; текст абзаца → тело экрана. Ink **не меняет
  состояние сам**: он вызывает внешние функции из белого списка (`give_kush()`, `set_name(…)`,
  `stat_check("observation", 5)`), их выполняет движок по правилам и данным. Переменные истории
  Ink (`story.state.toJson()`) хранятся в сейве.
- Тексты Ink — **наши** (D-01). Пишутся в Inky, компилируются в JSON при сборке.
- Без Ink (вариант Python): сцена — JSON-граф `{node: {text, choices: [{label, effect, next}]}}`.
  На 5–10 сцен MVP хватит, дальше станет тесно.

## 5. LLM-рассказчик (необязательно, после MVP)

Связь с **D-78 (ОТКРЫТО)**: там рекомендовано «правила детерминированные, LLM — только текст
поверх, с фолбэком». Для бота то же самое — и решение остаётся за пользователем. Довод D-78 против
облака («офлайн-игра») к боту не относится: бот и так работает через интернет.

### Принцип: факты решает движок, слова — рассказчик
1. Движок выполняет действие и выдаёт **структуру события**: `{kind: "search", place: "shop",
   found: [...], noise: 12, encounter: null, kislyak_in_min: 45}`.
2. Бот **всегда** собирает шаблонный текст из `ru*.json` — это и есть фолбэк.
3. Если рассказчик включён (глобально и у игрока), LLM получает событие и шаблон и возвращает 1–3
   предложения атмосферы. Цифры, предметы и исход **подставляет бот**, не модель: модель пишет
   «обёртку», а строки вида «+1 Споран», «Здоровье 64/110» идут из шаблона. Ответ проверяется:
   длина, запрет на числа и имена, которых нет в событии, — иначе шаблон.
4. Таймаут 3–4 с → шаблон. Ошибка API, исчерпан бюджет → шаблон. Игра не ждёт модель.
5. Голос Системы (лог) — **только шаблоны**: это главный голос игры (опора 2), его пишем руками.
   LLM — для описаний мест, тварей, реплик неписей, слухов.
6. Системный промпт: стиль, правила мира своими словами, **запрет цитировать и пересказывать
   книги**; книги и `docs/lore/` в контекст не кладём.

### Облачная или локальная

| | Облачная маленькая модель (Claude Haiku 5.5) | Локальная (llama.cpp / Ollama, 3–8 млрд параметров) |
|---|---|---|
| Качество русского | хорошее | у моделей 3–4 млрд заметно хуже; 7–8 млрд — терпимо |
| Задержка | ~1–2 с | на VPS без GPU — 5–15 с на 150 токенов, очередь при нескольких игроках |
| Железо | не нужно | Mac с Apple Silicon (бот работает, пока Mac включён) или VPS с GPU (дорого) |
| Деньги | за токены (ниже) | электричество / аренда |
| Приватность | текст событий уходит провайдеру (в событиях нет личных данных) | всё у себя |

**Оценка цены облака** (цены на 2026-10, перепроверить перед запуском): Claude Haiku 5.5 —
$0,10 за 1 млн входных токенов, $0,50 за 1 млн выходных, чтение из кэша ~×0,1. На одно описание:
системный промпт ~1 500 токенов (кэшируется, префикс от 512 токенов) + событие и контекст ~400 +
ответ ~150 токенов ≈ **$0,0001–0,0002** (думание выключить или минимальное усилие — для коротких
описаний оно не нужно). Сессия в 100 описаний — около 2 центов; 1 000 таких сессий — ~$20.
Sonnet 5.5 ($2 / $10) — в ~20 раз дороже; для рассказчика не нужен.

**Рекомендация**: MVP — без LLM (шаблоны). Потом, если пользователь решит, — облачный Haiku с
месячным лимитом бюджета, флагом на игрока и кэшем промпта; локальную модель — только как
эксперимент на Mac. Числа и исходы LLM не трогает никогда.

## 6. Развёртывание
- **Long polling** (без домена и TLS) — для одного процесса на VPS проще всего. Вебхук — когда
  понадобится масштаб.
- VPS на 1 vCPU / 1 ГБ хватит; `systemd` или Docker, Node LTS. Секреты — токен бота (и ключ LLM,
  если будет) — в `.env`, не в git.
- Ограничения Telegram, которые надо учесть: текст сообщения ≤ 4096 символов; `callback_data` ≤ 64
  байт (кодируем коротко: `a:srch:3:n7f`); не чаще ~1 сообщения в секунду в один чат — поэтому
  экран редактируется, а мелкий лог копится в подвале; всегда `answerCallbackQuery`. Разметка —
  HTML (`<b>`, `<i>`, `<pre>` для карты, `<blockquote>` для лога Системы).
- Закрытый доступ: белый список id в базе, команда администратора `/invite`.
