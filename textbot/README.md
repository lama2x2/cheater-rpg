# textbot — книга-игра в Telegram

Движок текстовых квестов для закрытого семейного бота (вход — по заявке, пускает админ). Кампания — папка YAML в `campaigns/`;
движок от неё не зависит. Бот — **сборник историй**: `/menu` показывает библиотеку (карточки без спойлеров, отметка
«пройдено»), у каждой истории свои три слота сохранений. Демо (`demo`, `demo_real`) скрыто из
библиотеки и нужно для тестов.
Дизайн и формат кампании — `docs/text_rpg/` (особенно `campaign_format.md`).

Неофициальная некоммерческая фанатская игра в мире цикла «Читер» Артёма Каменистого. Тексты свои.

## Запуск (Docker)

1. **Docker.** Установите Docker Desktop (Mac/Windows) или Docker Engine (Linux) и запустите его.
2. **Бот.** В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot` → придумайте имя
   и логин (должен кончаться на `bot`). BotFather пришлёт **токен** вида `123456789:AA…`.
   Никому его не показывайте.
3. **Настройки.** В папке `textbot/`:
   ```bash
   cp .env.example .env
   ```
   Откройте `.env`: вставьте токен в `BOT_TOKEN=`, а в `ADMIN_IDS=` — свой Telegram-id (узнать —
   у [@userinfobot](https://t.me/userinfobot); админов можно несколько, через запятую).
4. **Запуск.**
   ```bash
   docker compose up -d --build
   ```
5. **Пустить семью.** Админ сначала сам пишет боту `/start` (иначе бот не сможет ему писать).
   Остальные находят бота и жмут `/start` — видят «Заявка отправлена, ждите», а админу приходит
   карточка: имя, @username, id и кнопки **✅ Пустить** / **⛔ Отказать**. Пущенному приходит
   приветствие и начало игры, отказанному — вежливый отказ (повторные заявки от него админу больше
   не приходят; от ждущих — не чаще раза в сутки). Команды админа: `/users` — все заявки и
   статусы, `/approve <id>` — пустить, `/revoke <id>` — закрыть доступ. Админ из `ADMIN_IDS`
   пущен всегда. Решения хранятся в базе (`data/textbot.db`), `.env` трогать не нужно.
6. **Играть.** `/start` — продолжить последнюю историю; `/menu` — истории, у каждой свои три
   слота; `/chapters` — главы текущей истории: вернуться к главе или скопировать её в другой слот
   (чтобы попробовать другие выборы); `/status`, `/memento` (концовки и смерти), `/about`.

Проверка: `docker compose ps` — статус `healthy`; журнал — `docker compose logs -f`
(и файл `data/logs/bot.log`).

Бот сохраняет игру после **каждого** выбора. После перезапуска контейнера или компьютера игрок
пишет `/start` или жмёт любую кнопку — и продолжает с того же места. Старые кнопки не ломают
игру: бот отвечает «Экран обновлён» и показывает текущий экран.

## На сервере (VPS)
Бот живёт на VPS в `/opt/gaz_quest_bot` (тот же `docker-compose.yml`, своя база в `data/`).
**Локально с тем же токеном не запускать**: два polling-а одного бота конфликтуют.

Обновить код и кампании (база и `.env` на сервере не трогаются):
```bash
./deploy.sh news.txt
```
Адрес берётся из локального `.env`: `DEPLOY_HOST=root@<ip>`, `DEPLOY_PORT=2222`. Перед
выкладкой — `python -m textbot.lint campaigns/<id>` и `pytest`.

**Правило: каждое обновление — с рассылкой всем игрокам.** `news.txt` — короткое описание
обновы для игроков (что нового: истории, главы, исправления; без технических деталей).
Без файла скрипт не выкладывает; после выкладки, когда бот здоров, он рассылает текст всем
пущенным игрокам и админам (`python -m textbot.broadcast`, `--dry-run` — проверить). Файлы
`news*.txt` в git не идут.

## Бэкап
- Автоматически: раз в сутки (и при каждом старте) копия базы в `data/backups/`, хранятся 7
  последних.
- Вручную:
  ```bash
  docker compose exec bot python -m textbot.backup
  ```
- Восстановить: `docker compose down`, скопировать нужный файл из `data/backups/` в
  `data/textbot.db` (старый — сохранить рядом), `docker compose up -d`.
- Папку `data/` целиком стоит иногда копировать на другой диск или в облако.

## Править кампанию
Кампании лежат в `campaigns/` и подключены в контейнер «только для чтения» — пересобирать образ
не нужно. После правки:
```bash
python -m textbot.lint campaigns/demo
docker compose restart
```
Бот не стартует, если в кампании есть ошибки (их видно в `docker compose logs`). Старые сейвы
переживают правки: см. «Правки кампании и старые сейвы» в `docs/text_rpg/campaign_format.md`.

## Инструменты (без Docker)
```bash
python3.12 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
```
- `python -m textbot.lint campaigns/demo [--mode real]` — битые ссылки, тупики, недостижимые
  сцены, неизвестные флаги и переменные, длина текста, хабы без `again`, реплики с пустым или
  повторяемым ответом; `--entries` — входы в сцены с несколькими входами, чтобы вычитать склейки.
- `python -m textbot.play campaigns/demo [--mode real]` — играть в терминале.
- `python -m textbot.autoplay campaigns/demo -n 2000` — случайные прохождения: тупики,
  зацикливание, все ли концовки достижимы, распределение концовок; и экраны глазами игрока —
  абзац, повторённый на одном из недавних экранов, пустой или слишком длинный экран, заход
  в сцену, где делать уже нечего.
- `python -m textbot.autoplay campaigns/demo --screens [--seed N]` — экраны одного прохождения
  подряд, как в чате; повторы помечены ⟳.
- `python -m pytest` — тесты движка, языка условий, сохранения и «рестарта».
- Запуск бота без Docker: `BOT_TOKEN=… ADMIN_IDS=… python -m textbot` (данные — в `data/`).
